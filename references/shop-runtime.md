# XXD Shop 士兵运行时

本文件是每个编号 `xxd-shop-NNN` 士兵共用的家族运行合同，逐字复制到每个士兵的 `references/shop-runtime.md`。它不是美学提示词，永远不能替代 `references/original-prompt/zh-CN.md`。

每次构建生图请求之前，完整读取本文件。编号 `SKILL.md` 可以写本编号专属覆盖条款。覆盖条款可以追加约束；只有在原始提示词明确要求时，才可以改变某个参数在本编号的默认值，或补充本合同没有覆盖的流程（例如逐页生成）。覆盖条款不能放宽事实纪律、隔离与验收，也不能改写原始提示词。

## 权威边界

1. 每次构建生图请求之前，完整读取 `references/original-prompt/zh-CN.md`。这份中文原始提示词是唯一的创作与审美权威。
2. 若首行 Markdown 标题只是归档标签（例如 `# Original XXD Shop NNN style brief`），生图请求中省略这一行，其余正文逐字使用。不总结、翻译、润色、扩写、重新诠释，也不用 `SKILL.md`、README、样张、本文件或 `original-prompt/` 下的阅读译文替换它。译文只供国际读者阅读和转发，不是运行时备选提示词。
3. 原始提示词负责：商品如何呈现、场景与承载关系、光线、色彩逻辑、材质、构图、留白、文字多少与写法、字体气质、贴纸／标签／信息组织，以及全部禁止项。
4. 运行时只负责：本次商品是谁、每张参考图承担什么角色、哪些事实可以上画面、用户的准确文案、目标语言、最终画布、张数与输出位置。
5. 所有运行时内容一律追加在原始提示词正文**之后**，不插入、不改写其中任何审美段落。
6. 外层 Skill 不另做配色方案、不提炼色卡、不预写标题或文案包、不发明“美学动机”、不套外部营销框架。原始提示词自己要求分析卖点、生成贴纸语或决定价格存在感时，交给图像模型按原文执行。
7. 原始提示词中出现的“用户提供……”“若只提供产品名称……”等分支，由本次商品块提供的真实输入触发；运行时不替用户选择分支。
8. 样张只展示结果，不复制其中的商品、颜色、文案、版式偶然性或比例。

## 本次商品与参考图角色

每次调用都是一个新任务；只有用户明确要求查看、修改、继续或复用某个已命名结果时例外。相同请求也必须重新生成、新建任务目录，旧文件不能冒充本次成品。

可接受的输入：

- **商品图**（实拍、白底、包装、多角度、细节）：商品身份的最高依据。锁定造型、比例、结构、包装、颜色、材质、Logo、包装文字及位置；允许按新场景重建光线、阴影、反射、透视与环境色。
- **Logo / 品牌标识图**：只锁定标识本身，不继承其背景。
- **场景或风格参考图**：只有用户明确说明用途时才使用，只作用于用户说明的那一项，不能把参考图里的其他商品、文字或品牌带进来，也不能压过原始提示词的审美。
- **文字输入**：商品名称、品类、规格、口味、卖点、用途、品牌气质或创意命题。没有商品图时，它就是原始提示词“只提供产品名称、品类或创意命题”的那条分支。
- **文字资料**（说明书、PDF、规格表、检测报告、活动文案文档）：由 Agent 阅读，只把其中的事实整理进“可用事实”，或把文案整段交给文字块；不作为参考图送进生图。

同一商品的多张图共同作为外观依据。不同商品、型号或套装混在一起且本次对象不清时，先问清本次商品与每张图的归属；不清楚前不生成，不把多件商品的结构、颜色或 Logo 混成一件新商品。

参考图的用途无法判断时，只问这一张图的角色，不笼统追问。

## 事实纪律

电商画面里看起来像事实的信息，必须有来源：

- 可以上画面的事实只来自三处：用户本次提供的、商品图上清楚可读的、本次已经核实并记录来源的。三处的事实都由 Agent 逐条写进本次商品块的“可用事实”并注明来源（`用户`、`包装`、`核实：<链接>`）；图像模型只能用“可用事实”里的条目，不自己从包装上读数字再写成新文案。包装上原有的文字本身照常保留。
- 价格、折扣、规格、成分、产地、功效、销量、排名、评分、奖项、认证、年份、日期、合作方、库存等，没有来源时一律不写；不编造，也不用“约”“近”之类的写法暗示数字。
- 画面上的推荐语、贴纸语按三级处理，各编号覆盖条款只能在此基础上收紧：

| 级别 | 例子 | 处理 |
|---|---|---|
| 一、语气与描述 | 口味、口感、气质、情绪；“招牌推荐”“必点”“经典”“店长推荐”这类卖家自己的推荐语气 | 原稿要求时，图像模型可按原文生成 |
| 二、卖家状态 | 新品、限定、季节限定、今日特供、每日现做、新鲜出炉、预售 | 只有用户本次说过才用 |
| 三、可核查事实 | 热销、人气、口碑、销量、排名、评分、获奖、认证、老字号年份、“XX 榜” | 只来自“可用事实” |

  拿不准属于哪一级时按更严格的一级处理。
- 原始提示词要求先检索、核实术语或结构时（例如面料、技术、零部件），由 Agent 在生成前用可用的检索工具查证，优先品牌官方、厂商技术资料、行业或标准资料。把核实结果和来源写进任务目录的 `facts.md`，只把已核实的结论放进本次商品块。检索不足时删去该主张或问用户，不猜测。
- 用户提供的未公开资料、商品图不送入外部检索。

## 只解析运行变量

### 行内快捷参数

调用之后任何位置都可以写参数：

```text
/xxd-shop-NNN <商品图、图片目录或商品名称> \
  --product "冷萃咖啡液 · 12 颗装" \
  --size auto,1:1,3:4 --count 2 \
  --text prompt --locale zh-CN \
  --facts "规格 25ml×12；产地 云南保山"
```

把 `NNN` 换成当前士兵编号。可接受的参数：

- `--product`：本次商品名称、品类或创意命题。有商品图时用来称呼和补充信息；没有商品图时它就是创作依据。
- `--use`：用途，例如电商主图、详情页首屏、海报、品牌 KV、小红书、横幅。用途帮助推荐画幅，原样写进商品块的“用途”行，不改变原始提示词的审美。
- `--focus "..."`：本张重点，即原始提示词留给用户决定、而编号覆盖条款点名可以由用户指定的那一项（例如 009 的“本张任务”、011 的“价值主轴”、014 的“源头与终点”、015 的“互动动作”）。原样写进商品块的“本张重点”行，并在行首标明它对应原稿里的哪个概念（由覆盖条款点名），让图像模型把用户的话接到原稿的那条要求上；没有给时由图像模型按原稿判断。覆盖条款没有点名的编号，`--focus` 按“用户其他明确要求”处理。
- `--size`：一个或多个 `auto`、`source`、`1:1`、`3:4`、`4:3`、`4:5`、`5:4`、`2:3`、`3:2`、`9:16`、`16:9`、`21:9`，任意自定义比例，或准确的 `宽x高`。可重复，逗号分隔，接受 `×`。
- `--count`：每件商品、每个尺寸生成几张彼此独立的完整构图，默认 1，不单独询问。总张数 = 商品数 × 尺寸数 × count。每一张都从本次原始输入单独生成，不从上一张改出来（启用“系列锚定”的编号除外，见同名章节）。
- `--text`：`prompt`、`exact`、`plan` 或 `none`。
- `--copy "..."`：用户的文案。单独使用时隐含 `--text exact`（逐字使用，不改写、不翻译），除非编号覆盖条款按原稿另定默认（例如 010 默认按文案方案处理）；与 `--text plan` 同用时，它是一份“文案方案”，见下文文字块。
- `--facts "..."`：用户允许上画面的事实（价格、规格、产地、成分等），逐条使用，不润色成别的数字，也不改写事实的名称（例如“原价”不换成“日常价”“划线价”）。
- `--locale`：画面文字的语言、市场或地区。
- `--logo <路径>`：品牌标识图。
- `--ref <路径>=<用途>`：带明确用途的场景或风格参考图，可重复。
- `--out`：指定输出根目录。
- `--prefs`：`last`、`edit`、`new`、`off` 或 `clear`，控制是否沿用 XXD Shop 家族记住的交付偏好。

显式参数优先于含糊的描述。多值参数按用户顺序累积去重，单值参数取最后一次。所有必需变量都已确定时跳过问询直接生成；只缺一部分时只问缺的部分。`--text none` 与 `--copy` 同时出现这类直接矛盾，要先问清。

### 沿用上次偏好

解析完本次描述和参数后，完整读取 [runtime-preferences.md](runtime-preferences.md) 并照做，再进入普通问询。仍有未确定项、且存在有效记录时，给出三条路线：直接沿用、沿用并修改、全新配置。本次已经完整指定时直接走快捷路径，不问这一题。

### 目录批量

用户给的是一个可读目录，就是明确的批量意图，直接进入批量流程。

1. 递归清点支持的位图（`.png`、`.jpg`、`.jpeg`、`.webp`、`.heic`、`.heif`、`.avif`、`.tif`、`.tiff`、`.bmp`，不区分大小写）。用户要求只看顶层或排除某些文件时照做。
2. 忽略隐藏文件与隐藏目录、非图片、本 Skill 的输出目录，以及位于该目录内的输出根目录。不跟随解析后跳出该目录的符号链接。
3. 按相对路径自然排序。生成前报告找到的数量和递归范围，指出无法读取或解码的文件，不静默跳过。一张可用图片都没有时停止，不创建空任务目录。
4. 默认每张图片是一件独立商品，一张图一个队列项。用户说明“同一商品的多角度”或给出“商品 → 图片”的分组时，按分组建队列项。整个批量都使用当前编号和不变的原始提示词，不切换、不混用其他编号。
5. 尺寸、张数、文字方式、语言和输出位置对整个批量只确定一次。`auto` 与 `source` 按每张图分别计算。生成前说明输入数量、公共设置、个别例外与预计输出总数。
6. 每个队列项在逻辑上完全隔离：重新读取原始提示词，独立构建提示词，不把其他商品的内容、名称、事实、文案或结果带进来。唯一例外是编号启用的“系列锚定”：已确认的定调图可以作为后续队列项的参考，只传递覆盖条款列出的那几项。
7. `--text prompt` 为每件商品独立生成文字。单个 `--copy` 或 `--facts` 会用于每一件商品；不同商品文案或事实不同时，接受“相对路径或文件名 → 文案／事实”的映射，并在生成前逐项核对。一件商品的文案和事实绝不复用到另一件。
8. 某一项失败时，点名报告，不连带丢掉后面的队列项；只对失败项按单张重试规则处理，最后给出成功与失败的数量和路径。

一次批量只建一个物理任务目录，不为每个商品各建一个。

### 按宿主能力问询

不为了获得问询界面而把会话切到 Plan 模式。按实际可用的问询工具处理：

1. **有真正的多选工具**（例如 Claude Code 的 `AskUserQuestion`，`multiSelect: true`）：尺寸用真正的多选；文字方式用单选；`常用比例` 被选中时，再按宿主选项上限分组展示具体比例。已在描述或参数里确定的项不再问。

无论用哪种方式问，都先应用编号覆盖条款：覆盖条款排除的选项不出现（例如 012 没有“不要文字”），标为推荐的选项放第一位并注明；覆盖条款声明“不问文字方式”的编号（例如 005、008、011、013、015）直接按其默认执行；原稿已固定的画幅或语言不再问，只在生成前的说明里写出。文字方式选“不要文字”，或覆盖条款声明本编号的“按原稿生成”不新增文字时，不问语言。
2. **只有单选工具**（例如 Codex `request_user_input`）：只用于真正单选的字段（文字方式、尺寸入口）。尺寸这种多值字段用下面的文字组合输入收集，不把单选卡片说成多选。
3. **没有问询工具**：用下面的文字组合输入。这是打字输入，不画 `- [ ]` 之类的假控件。

文字组合输入（只列出仍未确定的项）：

```text
请选择尺寸，可多选：

1. 智能推荐（显示本次按用途和原稿计算出的比例与像素）
2. 跟随商品原图
3. 常用比例（直接写 1:1、3:4、9:16 等一个或多个）
4. 自定义（一个或多个比例／准确像素）

请选择文字方式：

A. 模型按原始提示词生成文字（注明语言或地区）
B. 使用我的准确文案，一字不改（发送原文并注明语言或地区）
C. 我给文案方案，允许按原稿压缩、理顺层级，但不改意思、不加事实
D. 不要文字

可回复：尺寸 1＋3:4；文字 A，简体中文
可回复：尺寸 1:1；文字 B，准确文案「……」，简体中文
```

只回答 `常用比例` 时，展示一次比例库：

```text
方形：1:1
竖版：3:4、4:5、2:3、9:16
横版：4:3、3:2、16:9、21:9
也可以直接写准确像素。
```

商品图和商品名称都没有时，先问商品，不问尺寸。编号 `SKILL.md` 声明“必须有商品图”时，没有商品图就只请用户上传，不用文字描述、检索图片或凭空生成代替真实商品。

不要根据人物外貌、文件名、元数据、包装上的外文、招牌或用户操作 Skill 时用的语言推断画面文字语言；需要文字时明确确认语言。原始提示词自己规定了文字语言（例如“手写英文”“中英双语标题”）时，语言已由原稿确定，不再询问；用户明确要求另一种语言时，说明这会偏离原稿哪一点，按用户的决定执行。准确文案逐字传递。原始提示词要求的大标题不能缩成一行小字。若“不要文字”会毁掉原稿依赖文字的核心语言（例如以产品名为主视觉的版式），先说明冲突、问清再花生图额度，不悄悄改掉。

### 尺寸

- 没有静默默认比例。
- `auto`：根据用途、原始提示词与商品形态推荐整张画布比例，并显示比例和像素。常见对应：电商主图 `1:1`；详情页首屏、小红书 `3:4`；竖屏信息流、开屏 `9:16`；横幅、品牌 KV `16:9` 或 `3:2`。原始提示词自带固定画幅或方向时（例如“竖版”“横版 16:9”），`auto` 采用原稿画幅；用户明确选了相反方向时，说明一次冲突，按用户的决定执行。
- `source`：采用商品原图的长宽比。
- 准确像素优先于比例。只给比例时，默认换算为长边 2048、短边按比例取最接近的 16 的倍数（例如 `1:1`→`2048x2048`，`3:4`→`1536x2048`，`9:16`→`1152x2048`，`16:9`→`2048x1152`）；编号覆盖条款另有规定时从其规定（例如 012）。
- 每个不同的长宽比都是一次独立的完整构图，同一原始输入、同一逐字原稿；不从一个比例裁出另一个比例。同一比例的多个分辨率可以从验收通过的那张导出。
- 生成前说明：已确定的尺寸（比例与像素）、每件商品每个尺寸的张数、文字方式与语言、输出总数。都已完整且一致时，不再要求二次确认。

## 构建生图提示词

每一张成品，按顺序拼接：

```text
[references/original-prompt/zh-CN.md 正文，逐字；仅省略归档首行标题]

[本次交付块]
[本次商品块]
[一个文字块]
[用户其他明确要求，逐字，若有]
```

本次交付块：

```text
【本次交付｜当前成品】

本段只决定画布、张数与生成方式，不改变上文原始提示词的任何审美要求。

最终画布：<比例和／或准确 宽x高>
本张序号：<本商品、本尺寸的第 i 张 / 共 count 张；count＞1 时，每张是独立的完整构图，不是同一构图的微调>
生成方式：一次生成一张完整画布，从本次原始输入单次直达
不额外添加：画布外的边框、拼贴、多图总览、水印或界面元素
颜色与光线完全服从上文原始提示词；除非用户明确要求，不另做配色。
```

本次商品块：

```text
【本次商品】

商品：<--product 或从商品图可辨认的品类称呼；看不清品牌时不编造品牌名>
用户描述：<用户关于商品的其他文字输入（卖点、口味、气质、场景等），原话；没有则省略此行>
用途：<--use，若有>
本张重点（对应原稿的「<覆盖条款点名的原稿概念>」）：<--focus，若有>
参考图角色：
- 图 1：<商品图｜锁定造型、比例、结构、包装、颜色、材质、Logo 与包装文字，不改款、不重绘包装文字>
- 图 2：<Logo｜只锁定标识，忽略其背景>
- 图 3：<用户说明的参考用途，只作用于该项>
（没有任何参考图时写：无参考图，按商品名称、品类与属性建立可信的商品形态。）
可用事实：<--facts 与已核实事实，逐条，注明来源；画面上使用时数字与名称都原样，不换近义说法；没有则写“无，画面不出现任何事实性数字、资质或排名”>
```

文字块四选一：按原稿生成、用户准确文案、用户文案方案、不要文字。

模型按原始提示词生成文字：

```text
【文字方式：按原始提示词生成】
文字语言：<已确认的语言或地区>

是否出现文字、出现多少、写什么，由上文原始提示词的文字逻辑决定。
文字只围绕本次商品生长；任何看起来像事实的信息（价格、规格、产地、功效、
销量、排名、奖项、认证、日期）只能来自“可用事实”，没有就不写。
商品包装上原有的文字保持原样，不改写、不翻译、不重排。
原稿要求的大标题不得缩成小字。
```

使用用户准确文案：

```text
【文字方式：用户准确文案】
文字语言：<已确认的语言或地区>
文案：「<用户准确文字>」

逐字使用，不改写、不翻译、不纠错、不添加其他文案。层级、字体气质与位置继续服从原始提示词。
商品包装上原有的文字保持原样。
```

使用用户文案方案（`--text plan`）：

```text
【文字方式：用户文案方案】
文字语言：<已确认的语言或地区>
文案方案：「<用户提供的全部文案>」

先分析这份方案的结构与主次，提炼主标题、副标题、卖点句、补充信息与强调词，
再按上文原始提示词的层级落地。允许压缩、合并、调整顺序、强化层级；
不改变核心意思，不新增方案里没有的事实、数字或承诺，不翻译成其他语言。
方案是文字的上限：不另写方案里没有的新句子、口号、解释性小字或功效说法；
商品名称与“可用事实”里的条目可以作为文字出现，措辞原样。
商品包装上原有的文字保持原样。
```

文案方案不是让外层 Skill 改写：Agent 把用户原文整段放进上面的块，由图像模型按原稿处理，外层不预先改好再交给模型。

不要文字：

```text
【文字方式：无】
除商品包装本身已有的文字与 Logo 外，画面不出现任何新增的字母、文字、数字、标题、标签、贴纸文字或伪文字。
```

用户明确要求修改颜色或其他风格变量时，把原话放在最末尾，标为用户覆盖，不展开。

生成前检查：提示词里只有一个文字块、一个交付块、一个商品块；原稿正文与归档文件逐字一致；“可用事实”里的每一条都能指出来源。

## 系列锚定（仅限编号覆盖条款启用）

默认每张成品都只从本次原始输入单次生成，互不参考。只有编号 `SKILL.md` 明确启用“系列锚定”时（例如原稿要求一套系列海报“放在一起明显属于同一个品牌世界”，或逐页手册“后续页继承前页品牌系统”），才按下面执行：

1. 先生成第一张作为定调图，交给用户确认。用户不满意就只重做定调图，不往下走。
2. 定调图确认后，后续每一张都同时参考：本张自己的原始输入（商品图等）＋已确认的定调图。定调图只传递原稿要求保持一致的那几项（由覆盖条款写明，例如字体气质、色彩情绪、品牌识别），每张仍然重新构图。
3. 不从定调图裁切，不链式派生：第 3 张参考的是定调图，不是第 2 张。覆盖条款另有规定（例如手册的已确认标志页）时，以覆盖条款列出的锚定图为准，最多三张。
4. 交付块里写明：`系列锚定：参考图 X 是已确认的定调图，只继承 <覆盖条款列出的项>，不复制其构图、商品或文字。`
5. 多个尺寸：定调图在用户列出的第一个尺寸上生成。其他尺寸（包括定调商品自己的其他尺寸）都参考同一张定调图重新构图；定调只传递字体、色彩与识别，不传递构图，所以跨比例可以共用。
6. 用户明确说“不用等我确认”时，定调图生成后由 Agent 按验收标准自检；通过即继续，不通过先如实报告再重做定调图，不带着不合格的定调图往下走。

没有启用系列锚定的编号，`--count` 的每一张仍是彼此独立的构图。

## 位图执行

- **只走 `responses` 模式，绝不使用按张计费的 credit 路径。** 所有请求都发往 `/v1/responses`，由托管的 `image_generation` 工具出图；不调用 `/v1/images/generations` 或 `/v1/images/edits`，也不把它们当作备选、对比或兜底提出来。线路慢或限流时，只在 `responses` 内处理：换线路、等待或降低并发。
- 宿主暴露了内置生图工具、且它不走 credit 计费时，可以按已安装的 `imagegen` Skill 执行，每张成品一次调用。
- 否则使用 `scripts/configured_imagegen.py`（脚本路径相对当前 Skill 目录解析）：
  1. `lines`：列出可用的作图线路。装了 `xxd-prompt-image-batch` 时，线路来自它的线路表，密钥由它的 Keychain／配置查找，本 Skill 不另存任何密钥；没装时退回 Codex 配置里的当前供应商，同样走 `responses`。
  2. **每个任务开始前问一次用哪条线路**：把 `lines` 的结果按“编号　地址（host:port）　机器别名　模型　备注”逐行展示，推荐项标 ★，请用户回一个数字。同一任务后续每张图都沿用这个选择，不再问；新任务重新问。用户在同一条消息里已经点名线路、地址或模型时不问，说明解析到了哪一条。
  3. `probe --provider N`：只检查线路是否有响应，不出图、不计费。
  4. `generate --provider N --prompt-file <私有临时文件> --out <png> --size <宽x高> --image <商品图> [--image <其他参考图>]`：第一张 `--image` 放商品主图；完全没有参考图时不加 `--image`。所选线路失败时，自动按线路表里该线路的备用顺序切换，`--no-failover` 只用这一条。
- 脚本的输出只含线路别名、地址、状态与路径，永不打印密钥、请求头、完整提示词或响应正文。不手动查看密钥或配置文件；除非用户单独明确要求，不修改线路表、账户、计费或全局路由设置。
- 输出 `"prompt_rewritten": true` 表示中转模型改写了提示词，要如实告诉用户。
- **线路实际返回的像素可能低于请求**（`responses` 模式下常见）。脚本不放大冒充：比例不对时只按原生尺寸裁到目标比例，文件名里的像素改成实际像素，并输出 `delivered_size` 与 `size_matches_request`。交付时如实报告实际像素；用户需要更大尺寸时，说明这条线路的上限，由用户决定是否另行放大，放大后的文件要在文件名或报告里写明“放大”。
- 没有任何可用线路时，请用户启用线路或自愿提供本次任务用的 API Key；没有可信的脱敏结果前，不断言“缺少 Key”。
- 交付位图成品。SVG、HTML、CSS、Canvas、图表或程序绘制不能替代。

每张成品一次完整画布生成：把本次原始参考图、原稿正文、交付块、商品块、文字块与画布一次性交给图像模型。不预先裁切商品图，不分块生成再拼，不做第二轮图生图风格化。商品图背景杂乱且会干扰时，可以先抠出商品作为参考，原图同时保留作细节依据；抠图损坏边缘、透明部分或包装文字时丢弃抠图，改用原图。

某张未通过验收时，可以自动从本次原始输入重试一次，这一次不算超出约定张数；只补充真正失败的那条内容或交付约束，不从失败的成品继续改。重试后仍不通过，如实报告并问用户是否继续，不再自动重试。

## 资源纪律

只生成用户本次要的成品。样张是可选文档，永远不是运行前提；只有维护或制作样张时才看 `references/sample-workflow.md`。不因为没有样张就生成预览、备选风格或自动重试。验收失败或拿不准时如实报告，超出约定张数前先问。

## 输入与输出隔离

只使用本次附带的图片、明确给出的图片路径、明确给出的输入目录，或用户明确指认为“同一张”的先前图片。只在目录批量规则下扫描目录；不为了找替代素材去扫描桌面、工作区根目录、输出目录或无关目录。历史成品与样张不是输入。

所有成品直接写进一个新建的任务目录；任务目录是唯一的分组层级。编号 `SKILL.md` 写明默认根目录 `~/Desktop/xxd/xxd-shop-NNN/<新任务>/`，任务目录名为 `<YYYYMMDD-HHMMSS>-<简短商品名或品牌名>`。文件名示例：

```text
item-001-cold-brew-1x1-2048x2048-v01.png
item-001-cold-brew-1x1-2048x2048-v02.png
item-001-cold-brew-3x4-1536x2048-v01.png
item-002-oolong-tea-1x1-2048x2048-v01.png
facts.md（只有本次做过检索核实时才有）
```

多件商品用补零序号加清洗后的商品名或图片名（保留中文等可读字符，只去掉路径非法字符并把空格换成 `-`），其后是比例、像素与版本号。不同相对路径同名时，保留足够路径信息或加短后缀避免冲突。不建商品、尺寸或版本子目录，不生成拼贴总览、样机或合并预览。

`--out` 替换根目录，但仍要新建任务目录。生成前先占好不冲突的任务名。按商品顺序、尺寸顺序、版本顺序返回 PNG 的绝对路径。

## 验收

逐张以原尺寸和缩略图尺寸查看。全部满足才算通过：

- 是本次输入的新结果，张数、画布比例或准确像素、PNG 格式都与已确定的变量一致；
- 有商品图时，商品一眼可认：造型、比例、结构、颜色、材质、Logo、包装文字及位置没有被改款、重绘、错字、乱码或替换；没有被无关物体遮住关键识别部位；
- 没有商品图时，商品形态与名称、品类、属性一致，没有冒出不存在的品牌标识；
- 符合 `references/original-prompt/zh-CN.md` 的要求，尤其是它自己关于商品落点、光线、色彩、构图、文字层级与禁止项的规定，外层没有另加配色或美术指导；
- 画面上每一条看起来像事实的信息，都能对应到“可用事实”；准确文案逐字一致、没有附加；文案方案没有改变意思、没有新增事实；无文字模式没有新增文字或伪文字；原稿要求的大标题没有缩成小字；新增文字在缩略图尺寸下仍可读；
- 目录批量时，每个发现的输入在队列里恰好出现一次，所有成品都在同一个任务目录里，最终报告覆盖每一个成功与失败；
- 没有用 SVG 或代码绘制冒充，没有水印、界面元素、线路信息或密钥。

不通过时只针对失败的那条原稿要求或运行要求重试，不引入新的审美理论来“改进”。编号 `SKILL.md` 的覆盖条款可以追加验收项，不能放宽本节。

交付前，用可用的 `xxd-strip-ai-meta` 流程清理成品元数据，确认受支持的来源元数据已移除，保持像素与色彩配置不变。这只是元数据清理，不代表作品不是 AI 生成。
